Confirmed in interview 2026-07-29. Anything not listed here is undecided; see `99-open-questions.md`.

| #   | Decision                                                                           | Consequence                                                                                                 |

## Data-driven revisions

Added after profiling `test.csv` — see [07-data-validation.md](07-data-validation.md) for the evidence behind each.

| #   | Decision                                                                                                                            | Consequence                                                                                                                                                                                                                                                                         |
| --- | ----------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D21 | ~~Detection filter offers Detected / Not detected / Any record of examination~~ → **extended to four states by D40**                | Three options became four. The reasoning is unchanged; the "examined, no result recorded" state became searchable rather than merely described                                                                                                                                      |
| D22 | Colon-delimited attribute values are **expanded to ancestors at index time**, by a `path_hierarchy` tokenizer                       | `ectoparasite: flea` indexes as both itself and `ectoparasite`. Searching the parent finds children via a cheap `term`, no prefix query. Also fixes outcome pairing: `examined for: ectoparasite` pairs with `detected: ectoparasite: flea`. Done by an analyzer, not the ETL       |
| D23 | Multi-valued taxonomy columns are **split on `; `**, by a `pattern` tokenizer                                                       | Mandatory. `subfamily = "Arvicolinae; Arvicolinae"` and `suborder = "Echinostomata; Digenea"` both occur. A scalar `term` misses those records silently. Done by an analyzer, not the ETL                                                                                           |
| D24 | `locality_search_terms` is the **primary place field** (supersedes D10); ETL to emit it as an **array**, not a joined string        | Terms themselves contain commas, so splitting the joined form is lossy. The array enables exact matching and place autocomplete                                                                                                                                                     |
| D25 | Detection values indexed **both** as flat keyword arrays and as nested docs, **both derived from the same `attributedetail` parse** | Flat `term` filters serve queries with no method filter; nested only when method/date/determiner correlation is needed. One source, two projections — the joined top-level columns are a cross-check, not an input                                                                  |
| D26 | **Events are nested, and nested is the only path for date and place filtering**                                                     | Top-level `began_date` becomes display-only — it misses second events (`MSB:Mamm:321142` was encountered 2016-07-09 and 2016-08-12; top-level records only July). Cost: every date/place filter pays nested cost. Sorting uses derived, sort-only `event_date_min`/`event_date_max` |
| D27 | Keep **all** events; no deduplication, no preferred flag                                                                            | Duplicate georeferences — same date and locality, coordinates differing in the 4th decimal — stay as separate nested events. Result rows may show two coordinates for one specimen                                                                                                  |
| D28 | Records with **no collecting event are indexed**                                                                                    | Findable by taxon, catalog number, or attribute; date and place filters exclude them naturally. `MSB:Herp:57260` is the example                                                                                                                                                     |
| D29 | **No encumbered data in scope**                                                                                                     | ETL asserts `encumbrances` is empty and fails the build loudly if that changes upstream. A public portal must not start leaking silently                                                                                                                                            |
| D30 | ~~ETL **synthesizes inverse relation edges and resolves `MSB:Host` stubs**~~ → **withdrawn by D31**                                 | Was based on 37 relation rows. Both halves are wrong at scale                                                                                                                                                                                                                       |

## Revised against the full MSB slice

Added after profiling `msb.csv` (741,801 rows) — see [08-full-dump-validation.md](08-full-dump-validation.md).

| #   | Decision                                                         | Consequence                                                                                                                                                                                                                                                                                                                                                                                                     |
| --- | ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D31 | **Relations are copied, not derived** (withdraws D30)            | `host of parasite` exists natively — 54,059 rows against 57,485 `parasite of`, sitting on the host records. `MSB:Host` records are complete (100% `scientific_name`, 99.9% `collector_agents`, 97.6% `genus`), not stubs, and only 3.4% have the `same individual as` edge the traversal assumed. No inverse synthesis, no stub traversal, no `inferred` flag. The ETL normalises `record` to a GUID and copies |
| D32 | **Related-record filtering is family-level only in v2**          | The cache carries `family`, and both flagship queries filter at family (`Taeniidae`). The two-pass taxonomy join is deferred until someone needs a non-family related rank — it was the last piece of ETL that invents data the dump does not state                                                                                                                                                             |
| D33 | **Partial dates are handled by a `format` list, not by the ETL** | `attribute_date` has 7,099 `yyyy-MM` and 4,659 `yyyy` values; `began_date`/`ended_date` add datetimes. No garbage — every value is a valid ISO prefix. Field stays `date` with `strict_date_optional_time\|\|yyyy-MM-dd\|\|yyyy-MM\|\|yyyy`. **UI must state that a year-only date sorts as 1 January** and is missed by a mid-year range                                                                       |
| D34 | **Country/state/county are record-level only, never per-event**  | `json_locality` has no political geography — only `higher_geog`, a joined string. Splitting it positionally would be invention. Widens the D24/D26 tension, and that is the honest position                                                                                                                                                                                                                     |

## Revised against the Arctos code tables

Added after fetching the authority API — see [09-code-tables.md](09-code-tables.md).

| #   | Decision                                                                              | Consequence                                                                                                                                                                                                                                                                        |
| --- | ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D35 | **Attribute types marked `public: 0` are never indexed**                              | `NAGPRA category`, `restricted data` (_"Internal information of any sort"_), and `value`. Zero occurrences in `msb.csv`, which is why it must be enforced rather than observed — same hazard as D29. ETL drops them and fails the build on an undocumented type                    |
| D36 | **`/api/schema` sources vocabularies from the code tables, not `terms` aggregations** | The authority list is complete and carries descriptions; an aggregation returns only values that happen to be present, so an option silently disappears when a snapshot has no records for it. Aggregations stay, but only to attach **counts** — "0 records" is shown, not hidden |
| D37 | **Code tables label and document; they never validate**                               | A value absent from its code table is indexed and logged, never rejected. Making the data conform to its own documentation is sanitizing, not searching                                                                                                                            |

Everything from D21 onward had been derived from the data rather than confirmed. This round closed OQ1, OQ2, OQ7, OQ8 and OQ9, and reversed three earlier decisions.

| #   | Decision                                                                                                           | Consequence                                                                                                                                                                                                                                                                                                                         |
| --- | ------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D38 | **Netlify static hosting; the browser calls the Rust API directly** (resolves OQ1, supersedes D6)                  | Rust is a **public, unauthenticated, CORS-enabled API**. Every guardrail in spec 02 is now the only line of defence, not defence in depth. `svelte-adapter-bun` is the wrong adapter and must be replaced — see spec 02. No SvelteKit server runtime exists, so `load` runs in the browser and there is no server-side schema cache |

Preserves the D18 correlation the export would otherwise destroy. Only matching attributes, not every attribute                                                                 |
| D40 | **Outcome filter has four states** (extends D21)                                                                   | Adds _"Examined, no result recorded"_ as its own selectable option: `examined for` present, with no `detected`/`not detected` at that value **or below it** in the hierarchy. | D41 | **`snapshot_date` comes from an ETL-written metadata document** (closes OQ8)                                       | One doc per index recording extraction date, source filename, row count, and the code-table fetch date. ## Known tensions, accepted

- **D25 vs D26.** Nested-only events mean most queries already pay nested cost, blunting the flat-array fast path. It still avoids a _second_ nested query on the same request, so it remains worthwhile — but the win is smaller than D25 alone suggests.
- **D24 vs D26.** `locality_search_terms` is a record-level rollup, and a nested date cannot be correlated with a top-level place field. Correlated "at this place _on_ that date" needs per-event locality terms — see OQ13.
- **D11.** Free-text method matching over prose will have imperfect recall: `comb`, `combed`, `comb with chloroform`, and `comb w/chloroform` all occur in a 199-row sample. The form must say so rather than implying precision.
- **D27.** Keeping duplicate georeferences means any future per-event aggregation double-counts. Fine while there are no facets (D14); revisit if facets arrive.

## Stack already on disk

SvelteKit 2 / Svelte 5 / Vite 8 / TypeScript 6, `svelte-adapter-bun`, Bun lockfile, ESLint + Prettier. No app code yet — `src/` is scaffold only.

**`svelte-adapter-bun` is now wrong** (D38). It builds a Bun server; the decision is static hosting on Netlify with no server runtime. Replace with `@sveltejs/adapter-static` and an SPA fallback:

```js
// svelte.config.js
adapter: adapter({ fallback: '200.html' }); // Netlify's SPA fallback convention
```

`/search` takes arbitrary query strings and cannot be prerendered, so the fallback is required. `@sveltejs/adapter-netlify` is the alternative and is worth taking instead if SSR is ever wanted; it costs nothing today and leaves the door open. **Not yet changed in `package.json`** — it affects install and build, so it is called out rather than done.
